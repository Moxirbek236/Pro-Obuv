                    7. ROUTING & PERMISSION LOGIC
═══════════════════════════════════════════════════════════════════════════════

ROUTE PROTECTION STRATEGY:

1. PUBLIC ROUTES:
   - Accessible to everyone (authenticated or not)
   - Examples: /, /menu, /product/:id, /login, /register

2. AUTHENTICATED ROUTES:
   - Require any logged-in user
   - Check: session.user_id exists
   - Redirect to /login if not authenticated

3. ROLE-SPECIFIC ROUTES:
   - USER ONLY: /profile, /cart, /favorites, /user
   - STAFF ONLY: /staff/dashboard, /staff/menu, /staff/chat
   - SUPERADMIN ONLY: /super-admin/*, /admin/*
   
4. REDIRECT RULES:
   - If not logged in → /login
   - If logged in as USER trying to access STAFF page → /profile (or show 403)
   - If logged in as STAFF trying to access SUPERADMIN page → /staff/dashboard (or show 403)
   - If logged in as SUPERADMIN → Full access to all pages
   
5. POST-LOGIN REDIRECTS:
   - USER: → / or /menu (shopping page)
   - STAFF: → /staff/dashboard
   - SUPERADMIN: → /super-admin-control-panel-master-z8x9k

IMPLEMENTATION PATTERN (React Router):

```typescript
// ProtectedRoute.tsx
interface ProtectedRouteProps {
  children: React.ReactNode;
  allowedRoles: ('user' | 'staff' | 'superadmin')[];
}

const ProtectedRoute: React.FC<ProtectedRouteProps> = ({ children, allowedRoles }) => {
  const { user, role, isAuthenticated } = useAuth();
  
  if (!isAuthenticated) {
    return <Navigate to="/login" replace />;
  }
  
  if (!allowedRoles.includes(role)) {
    return <Navigate to="/unauthorized" replace />;
  }
  
  return <>{children}</>;
};

// Usage in routes:
<Route path="/profile" element={
  <ProtectedRoute allowedRoles={['user']}>
```

                        9. AUTH & STATE FLOW
═══════════════════════════════════════════════════════════════════════════════

AUTHENTICATION STATE MANAGEMENT:

1. AUTH CONTEXT:
```typescript
interface User {
  id: number;
  email: string;
  first_name: string;
  last_name: string;
  phone: string;
  address: string;
  avatar?: string;
}

interface AuthState {
  isAuthenticated: boolean;
  user: User | null;
  role: 'guest' | 'user' | 'staff' | 'superadmin';
  loading: boolean;
}

interface AuthContextType extends AuthState {
  login: (credentials: LoginCredentials) => Promise<void>;
  logout: () => Promise<void>;
  register: (data: RegisterData) => Promise<void>;
  checkAuth: () => Promise<void>;
}
```

2. AUTH FLOW:
   a. On app load:
      - Call GET /api/auth/status
      - If logged in, set user and role in context
      - If not, set role='guest'
   
   b. On login:
      - POST to appropriate login endpoint
      - On success, update context with user data and role
      - Redirect based on role
   
   c. On logout:
      - Call appropriate logout endpoint
      - Clear context
      - Redirect to /login or /
   
   d. On protected route access:
      - Check isAuthenticated and role
      - Allow or redirect accordingly

3. PERSISTENT SESSION:
   - Backend uses session cookies (httpOnly, secure)
   - Frontend doesn't need to manage tokens
   - Just include credentials in fetch/axios requests
   
4. SESSION TIMEOUT HANDLING:
   - If API returns 401 Unauthorized, clear auth state and redirect to login
   - Show toast: "Session expired. Please log in again."

GLOBAL STATE MANAGEMENT:

1. CART STATE:
   - Sync with backend via API
   - Local state for optimistic updates
   - Persist cart count in context

2. USER PREFERENCES:
   - Language, theme, font size
   - Store in localStorage
   - Sync with backend for logged-in users

3. NOTIFICATIONS:
   - Fetch unread count on load
   - Poll or use WebSocket for real-time updates (optional)

ERROR HANDLING:

1. API ERRORS:
   - Network errors: Show toast "Network error. Please try again."
   - 400 Bad Request: Show validation errors
   - 401 Unauthorized: Redirect to login
   - 403 Forbidden: Show "Access denied" message
   - 404 Not Found: Show "Resource not found"
   - 500 Server Error: Show "Server error. Please try again later."

2. FORM VALIDATION:
   - Client-side validation before submit
   - Show inline error messages
   - Disable submit button during processing

3. LOADING STATES:
   - Show loading spinner during API calls
   - Disable buttons to prevent double-submit
   - Skeleton loaders for content

```typescript
// api/client.ts
import axios from 'axios';

const API_BASE_URL = import.meta.env.VITE_API_BASE_URL || '';

const apiClient = axios.create({
  baseURL: API_BASE_URL,
  withCredentials: true, // Important for session cookies
  headers: {
    'Content-Type': 'application/json',
    'X-Requested-With': 'XMLHttpRequest',
  },
});

// Request interceptor
apiClient.interceptors.request.use(
  (config) => {
    // Add any auth headers if needed (not required for session-based auth)
    return config;
  },
  (error) => Promise.reject(error)
);

// Response interceptor
apiClient.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      // Unauthorized - redirect to login
      window.location.href = '/login';
    }
    return Promise.reject(error);
  }
);

export default apiClient;
```

                    13. CODING STANDARDS & BEST PRACTICES
═══════════════════════════════════════════════════════════════════════════════

TYPESCRIPT:
- Use strict mode
- Define interfaces for all data structures
- Avoid 'any' type
- Use enums for constants
- Type all function parameters and return values

REACT:
- Use functional components with hooks
- Follow hooks rules (don't call in loops, conditions, etc.)
- Use React.memo for expensive components
- Implement error boundaries
- Use Suspense for lazy loading

NAMING CONVENTIONS:
- Components: PascalCase (e.g., ProductCard.tsx)
- Files: PascalCase for components, camelCase for utilities
- Variables/functions: camelCase
- Constants: UPPER_SNAKE_CASE
- CSS classes: kebab-case or use CSS-in-JS

CODE ORGANIZATION:
- One component per file
- Keep components small and focused
- Extract reusable logic into custom hooks
- Use composition over inheritance
- Separate business logic from UI

API CALLS:
- Use React Query for data fetching
- Handle loading, error, and success states
- Implement retry logic for failed requests
- Cache responses when appropriate

STYLING:
- Use Tailwind utility classes
- Create reusable component classes
- Maintain consistent spacing and sizing
- Follow mobile-first approach

PERFORMANCE:
- Lazy load routes and heavy components
- Optimize images (use WebP, lazy loading)
- Debounce search inputs
- Virtualize long lists
- Minimize re-renders with useMemo and useCallback

SECURITY:
- Sanitize user inputs
- Validate data on client and server
- Use HTTPS in production
- Don't store sensitive data in localStorage
- Implement CSRF protection (backend handles this)

ACCESSIBILITY:
- Use semantic HTML
- Add ARIA labels where needed
- Ensure keyboard navigation
- Maintain color contrast
- Provide alt text for images
